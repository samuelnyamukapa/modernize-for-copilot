## Decisions

1. **Skills, not commands.** A plugin skill is run as `/<plugin>:<skill> args`, and `$ARGUMENTS` is filled in. Rename the plugin to a short name so the commands read well. Proposed: plugin `modernize`, with skills `assess`, `map`, `brief`, and so on, invoked as `/modernize:assess billing`. That matches upstream's `/code-modernization:modernize-assess`.
2. **Scripts go through an MCP server.** It is launched with an explicit interpreter and `${PLUGIN_ROOT}` in `args`. Preflight reports which Python ran.
3. **Guard hook:** `bash` and `powershell` entries. Paths resolve against `input.cwd`. Edit tools are matched by name, and `apply_patch` patches are parsed. Shell commands get a conservative write-detector.
4. **Agents** are referenced as `<plugin>:<agent>` everywhere, in skills and in workflows.
5. **Dynamic workflows** are the primary fan-out path. The direct-subagent fallback stays for sessions without `--experimental`.
6. **Install** is from the marketplace. Git on `PATH` is a documented prerequisite.
